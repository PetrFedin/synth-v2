# Syntha V2: аудит оформления и интерфейса

Дата: 2026-10-15. Источник: чтение и подсчёт по реальным файлам `public/*.css`, `public/index.html`, `public/modules/omnidata-v14-*.js`, `ARCHITECTURE.md` §10. Интерфейс в браузере не открывался и не снимался: оценки внешнего вида, шрифтовой метрики и реальных контрастов в готовых экранах требуют скриншотов. Контрасты ниже посчитаны мной по формуле WCAG 2.x для пар цветов из токенов.

## 1. Главное

1. Оранжевая палитра (`#ff5b22`) сохраняется по решению владельца. Но на ней белый текст проходит только 3,10:1 (AA для обычного текста требует 4,5:1), а оранжевый текст на белом — те же 3,10:1.
2. Основной шрифт — Arial при базе 13 px, таблицы 12 px, заголовки таблиц 10 px; из 570 объявлений `font-size` в подключённых CSS 330 мельче 11 px (8, 8.5, 9, 9.5, 10, 10.5 px).
3. Слоёв много: 21 подключённый CSS-файл на 508 КБ и 4008 `!important`. Единый набор токенов есть (`--ods-*` в `omnidata-v14-role-system.css`), но рядом живут `--od14-*`, `--odr-*`, `--od8-*`, `--v5-*`, `--od7-*` и десятки жёстких hex.
4. Самое дешёвое улучшение — не новая палитра, а шрифт + токены контраста + единые состояния кнопок + граница 1px.

### 2.5 Состояния
В `role-system` есть part `empty` (min-height 120, по центру, цвет muted), alert/toast (min-height 40), ряд правил для пустых тулбаров. Отдельных стилей «загрузка» (скелетон/спиннер) и унифицированного «ошибка» в `role-system` не найдено (поиск по `skeleton|loading|spinner` в этом файле дал только комментарии про пустые элементы); в `ARCHITECTURE.md` состояния loading/empty/error описаны для экранов как требование. На экране не проверено.

### 2.6 Адаптивность и доступность
- Режимы просмотра: `html[data-viewport-mode]` = monitor / tablet / phone (`viewport-mode.js`, правила в `role-system` строки ~1000–1100); медиа-запросы 720, 900, 980, 1180, 1260, 1380 px. Медиа-запросы есть в 25 файлах, порогов много, не только трёх режимов.
- Цели касания: на планшете min 44×38; для телефона и desktop 34–36 px. Для WCAG 2.2 AA (2.5.8) достаточно 24 px; для iOS/Material рекомендовано 44–48 pt.
- `prefers-reduced-motion` найден только в `omnidata-v14-role-system.css`; `:focus-visible` — в 6 файлах из 28 (i18n, omnidata, styles, v13, v14-extensions, role-system); остальные слои фокус не стилизуют.
- Мелкий текст: 330 из 570 объявлений мельче 11 px — главный риск читаемости (но часть может быть в неподключённых или ограниченных областях, не проверено).
- Цвет как единственный носитель смысла: статусы имеют текст в пилюле (ARCH §10.8).

## 4. Выбор шрифта: Inter или Onest
Критерии: кириллица, цифры в таблицах, читаемость 12–13 px, лицензия (OFL), самохостинг, вес файла.

| | Inter | Onest |
|---|---|---|
| Кириллица | да | да (изначально проектировался с кириллицей) |
| Табличные цифры | да, фича `tnum` (известна по документации Inter; проверить на нашей сборке) | не проверено — требует проверки перед выбором |
| Использование в данных/дашбордах | очень распространён | реже |
| Рекомендация | основной | кандидат для сравнения на скриншотах |

Решение: брать Inter, пока Onest не проверен на `tnum` и ширине. Вывод основан на общей известности свойств Inter; в этой работе шрифты не загружались и не тестировались.

## 5. Как свести версии omnidata-vNN безопасно

1. **Инвентаризация (без изменений кода).** Для каждого из 21 подключённого + 7 неподключённых CSS собрать: размер, число `!important`, список селекторов, которые не перекрыты более поздним слоем (инструмент: coverage Chrome DevTools на 10 ключевых экранах).
2. **Токены.** Создать единый блок токенов в начале `omnidata-v14-role-system.css`: добавить новые (`--ods-color-accent-text`, `--ods-color-focus`, `--ods-shadow-1…3`, `--ods-radius-*`, `--ods-font-*`), а старые `--od14-*`, `--odr-*`, `--od8-*`, `--v5-*`, `--od7-*` сделать псевдонимами на новые (`--od14-accent: var(--ods-color-accent)`). Визуально ничего не меняется, зато появляется одна точка правды.
3. **Hex → токены** по одному слою, начиная с последних (v14-extensions, module-adapters) и фиолетового `bom.css`, `omnidata-v4.css`.
4. **Осиротевшие слои** (v3–v6, fidelity): доказать, что их никто не грузит (поиск по `index.html`, JS, `static-handler`, тестам), записать результат, затем править тесты и `static-handler` в одном PR вместе с удалением. Без доказательства не удалять.
5. **Каждый PR.** Обновить `ARCHITECTURE.md` §10 в том же PR; прогнать `validate:ui`, `validate:design-system`, `validate:ods-boundaries`, `npm test`; приложить скриншоты до/после.
6. **Мера прогресса.** Число подключённых CSS, `!important`, уникальных hex, объявлений `font-size` < 11 px — записывать до и после каждого шага.

## Что осталось неподтверждённым
- Реальный вид экранов (скриншоты не снимались); влияние фиолетового `bom.css` на готовый экран.
- Ширина колонок после замены шрифта; поддержка `tnum` в Onest.
- Вес и влияние 508 КБ CSS на загрузку.
- Какие JS-слои `omnidata-v*.js` реально влияют на DOM.
- Контраст реальных состояний (disabled, hover на строках, фокус) — рассчитаны только токены.
- Вопросы лицензии и политики зависимостей для набора иконок.
